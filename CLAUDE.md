# Panda Cooking — Front

Front em Next.js de uma rede de receitas (busca, receita com modo cozinha, publicar, comentar e favoritar). Projeto de portfólio; a API em Go está em `panda-cooking-go-api`.

## Stack

Next.js 16 (App Router) + React 19 + TypeScript · Tailwind CSS 4 · TanStack Query · Zustand (sessão só em memória) · React Hook Form + Zod · axios · Vitest + Testing Library (jsdom).

## Comandos

```bash
npm ci
npm run dev        # http://localhost:3000, precisa da API em API_URL (.env.local)
npm run lint       # ESLint, --max-warnings=0
npm run typecheck  # tsc --noEmit
npm test           # Vitest
npm run build
```

O jeito mais simples de rodar tudo é o `docker compose up` do repositório da API, com este repo clonado ao lado (`../panda-cooking-front`, ou `FRONT_DIR`). Lá o servidor do Next usa `API_URL=http://api:8080`. Os usuários de demonstração e a senha deles estão no seed da API (`internal/seed/seed.go`).

## Como se orientar

- Leia `docs/INDEX.md` e abra só o que a tarefa pede.
- Visual, componentes e acessibilidade: `docs/DESIGN.md`. Telas: `docs/PRD.md`.
- Rotas e respostas da API: `api/openapi.yaml` no repositório da API. Rota nova entra primeiro lá; o front só consome o que já está na `develop` de lá.
- Tarefas abertas são issues do GitHub. Os repos antigos da org Panda-Cooking (2023) são só referência.

## Regras gerais

- Escopo: uma tarefa por vez, ligada a uma issue. O que aparecer no caminho vira issue nova. Nada de dependência "para o futuro".
- Página não chama `api` direto: usa um hook (`src/hooks`) ou um service (`src/services`).
- Tipo novo da API entra em `src/types` com os mesmos nomes de campo (`snake_case`).
- TypeScript estrito; nada de `any` sem comentário dizendo o porquê. `eslint-disable` só na linha, com o motivo.
- Identificadores em inglês; textos da tela, comentários, docs e commits em português.
- **Nenhuma senha escrita em docs**, nem de teste ou de demonstração: diga onde ela é definida.
- Repositório público: nada de código, nome de cliente ou padrão interno de outra empresa.

## Checklist de segurança (toda mudança)

- [ ] Formulário valida com Zod usando os limites de `src/lib/limits.ts` (é só para o usuário; quem protege é a API).
- [ ] Nada de `dangerouslySetInnerHTML` com dado do usuário; link e imagem vindos do usuário só `http`/`https`.
- [ ] Rota que exige login está no `proxy.ts` e a página usa `useRequireAuth`.
- [ ] Dado de quem está logado fica sob a chave `["me"]` do TanStack Query.
- [ ] Nada de `NEXT_PUBLIC_*` com o que não pode ser público; nada da sessão no `localStorage`.
- [ ] Dependência nova necessária, mantida e limpa no `npm audit`.

Como cada risco é tratado: `docs/SECURITY.md`.

## Testes

- Teste fica ao lado do arquivo (`api.ts` → `api.test.ts`) e testa o que o usuário vê (texto, label, papel do botão), com o service ou o adapter do axios mockado e o `next/navigation` mockado. Nada de rede de verdade.
- Correção de bug vem com um teste que falha sem a correção.

## Git e PR

- Trabalhar a partir da `develop`; tudo entra por PR, nunca push direto na `main` ou na `develop`. Branches são apagadas depois do merge.
- O Victor faz os merges: squash na `develop`; `develop` → `main` sempre com merge commit (um check impede PR para a `main` vindo de outra branch).
- Conventional Commits em português, assunto em minúsculas. O título do PR segue o mesmo formato (a CI confere).
- Commits com a identidade do Victor, sem linha de atribuição de IA. Um assunto por commit; nunca commitar `.env`, `.next` ou `node_modules`.
- A integração do GitHub põe sozinha um rodapé "Generated by Claude Code" na descrição do PR (e o recoloca ao editar). Remover; se voltar, só dá para tirar à mão.
- A CI roda em PR e em push para `develop` e `main`. Atualização major de dependência é feita à mão, num PR próprio.

**Pronto** = funciona com `docker compose up`, tem testes, lint, tipos e build limpos, checklist revisado, docs atualizados e a issue fechada.

## Armadilhas do ambiente

- Na nuvem (Claude Code), nunca use `pkill -f` com um padrão que aparece no próprio comando bash (mata o shell). Use `pkill -x` ou `kill <pid>`.
- O service worker do Nossos Lugares, que também roda em `localhost:3000`, guarda `/_next/static/*` e entrega JavaScript antigo ao Panda (erro "isImageUrl is not a function"). Limpe os dados de `localhost:3000` no navegador.

## Manutenção dos docs

- Antes de uma tarefa, leia docs/INDEX.md e abra só o que ela pede.
- Ao terminar, se aprendeu algo não documentado que faria falta, registre no CLAUDE.md do módulo.
- Doc passou de ~150 linhas? Divida por subtema e atualize o INDEX.
- Decisão de arquitetura nova → arquivo novo em docs/decisoes/.
- Se o código contradiz o doc, o código vale: corrija o doc e avise.
